costtrace explain

costtrace traces

From the bill to the line of code.

The bill says which resource got more expensive after a deploy. Your OpenTelemetry traces say which code calls it. CostTrace compares the deployed service's traces before and after the deploy, finds the queries and calls that changed per request, and splits the measured cost change across them.

$ costtrace traces --traces ./otel-export --changes deploys.json --sha 7d24e0c --focus ./exports

Per request, not per day

Changes are measured per request to each endpoint, so more traffic is reported as traffic, not blamed on the code.

Patterns, with locations

Repeated queries (N+1), new calls, more calls and slower calls, each with the file and function from your traces.

Your traces, as they are

Reads OpenTelemetry exports (OTLP/JSON files) or a Jaeger-compatible query API. No new instrumentation and no agent to install.

Why CostTrace

Designed for a different question.

CostTrace is a local-first tool that measures how the changes you ship coincide with changes in your actual cloud bill, using your own FOCUS data, in your own CI. Estimators ask what a change should cost; budgets ask whether spend moved; FinOps platforms ask where the money went. CostTrace asks, right in the pull request: what did this change actually do to the real bill?

Measured, not guessed

What each change actually cost, read from your bill with your negotiated rates, not list-price estimates.

Per pull request, even for code

Cost changes are lined up with the deploys they coincide with, including changes with no infrastructure diff at all.

Down to the code path

With your OpenTelemetry traces, the cost change is followed to the queries and calls that changed, with file and function.

Transparent numbers

Runs on your own FOCUS export in your CI, and every figure comes with a ± range and a documented method.

What it catches

Every deploy, measured from the bill, whether the change was infrastructure, code or a clean-up.

New & resized infrastructure

A NAT gateway estimated at $310/mo that really costs $1,368, because data processing never shows up in a Terraform plan.

Application code

Queries, retries, log volume or LLM calls that raise the bill of unchanged resources, attributed to the PR that deployed them.

Savings

Deleted and downsized resources count as savings, so clean-up work gets the credit it earns.

Only real signals

Every figure has a ± range from daily variation, noise isn't listed as impact, and back-to-back deploys are kept apart.

How it works

No agents and no SaaS account. CostTrace runs in your CI or on your laptop against your own billing export.

  1. Tag

    Deploys stamp resources with costtrace_sha, _pr, _repo and _service. One convention that's valid on every cloud.

  2. Measure

    CostTrace reads your FOCUS export straight from S3, Blob Storage or BigQuery, and your deploys from GitHub deployments or a deploy log, then compares costs before vs. after each deploy.

  3. Attribute

    New, changed and removed resources, plus cost shifts from application code in the same service, each with a ± range. With traces, down to the queries and calls that changed.

  4. Report

    A PR comment kept up to date by the GitHub Action, a table, JSON, or a failed CI check when a change blows past its estimate.
